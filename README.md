# Jarvis — Telegram-first Knowledge OS

Личный AI-ассистент и база знаний: заметки, задачи, документы и секреты в
естественном диалоге через Telegram. Вторая точка доступа — **read-only MCP**
для OpenCode, чтобы coding-агент мог получить нужный контекст, но не мог
прочитать секреты и не мог ничего изменить.

## Что умеет

- **Понимает обычный текст**: «У меня появилась задача — обновить
  инфраструктуру», «Запомни, как я настраивал бэкап сервера» — ассистент
  предложит структурированную операцию и применит её только после подтверждения.
- **Задачи** с независимыми измерениями: группа («сегодня», «на этой неделе»,
  «долгосрочные», «когда-нибудь», «без группы») и конкретный дедлайн; списки
  вычисляются по календарю и часовому поясу, а не хранятся датами.
- **Комментарии к задачам** — добавление и редактирование прямо из карточки,
  либо естественным языком: «добавь к задаче про обновление: согласовать окно» —
  ассистент предложит подходящие задачи на выбор.
- **Знания**: заметки, инструкции, решения, справочная информация; категории
  управляются пользователем.
- **Полнотекстовый поиск** (PostgreSQL FTS, русская морфология) по знаниям,
  задачам и заголовкам документов.
- **Голосовые сообщения** — транскрибация (если настроен провайдер), исходный
  текст сохраняется рядом с распознанным результатом.
- **Документы** — файлы шифруются AES-256-GCM до попадания в постоянное
  хранилище; выдача файла через Telegram, безопасное удаление.
- **Секреты** — отдельное хранилище, отдельный ключ, значения не попадают в
  поиск, логи, AI и MCP; показ значения — отдельный сценарий с автоудалением
  сообщения.
- **Подтверждение значимых изменений**: любые создание/изменение/удаление — через
  `pending`-операцию с кнопками «Подтвердить / Изменить / Отменить», идемпотентную
  и ограниченную по времени.
- **Диалог переживает перезапуск**: состояние сценариев в PostgreSQL.
- **Improvement backlog**: технические сбои фиксируются автоматически, гипотезы
  об улучшениях — из диалога (с порогом достоверности); `/diagnostics` — сводка,
  карточки и статусы, `/export_issues` — выгрузка Markdown + JSON для ручной
  передачи в OpenCode. Подробно: [docs/diagnostics.md](docs/diagnostics.md).
- **AI-агент с инструментами**: обратитесь по имени — «Джарвис, какие задачи по
  проекту SuperSport ещё не закрыты?» — агент сам вызовет типизированные
  инструменты (задачи, проекты, знания), покажет реальные данные и предложит
  кнопки; удаление — только через подтверждение. Работа ограничена бюджетами
  (время, шаги, токены), повторные вызовы и циклы отсекаются, `/cancel`
  останавливает запрос. Подробно: [docs/agent.md](docs/agent.md).
- **Журнал чата за день**: диалог (текст, голос, команды, ответы бота)
  сохраняется с маскировкой секретов и выгружается командой `/export_chat`
  в Markdown + JSON — как backlog. Хранение ограничено
  `CHAT_LOG_RETENTION_DAYS`, отключается `CHAT_LOG_ENABLED=false`.
- **MCP для OpenCode**: read-only инструменты поиска знаний, инструкций, задач и
  контекста проектов.

Пример диалога:

> — Сейчас пришлю паспорт, сохрани его в личных документах
> — Хорошо. Пришлите файл одним сообщением — я проверю его, предложу название,
>   тип и категорию, а сохраню только после подтверждения.
> *[файл]* — **Сохранить документ?** Название: passport · Тип: другое ·
>   Чувствительность: чувствительная [✅ Подтвердить] [✏️ Изменить] [❌ Отменить]

## Архитектура

Модульный монолит: `bot` → `conversation`/`services` → `repositories` → `db`,
плюс изолированные адаптеры `ai` и `transcription`, сервисы `documents`
(шифрованное хранилище), `secrets`, `search`, `security` и отдельный процесс
`mcp`. Подробно: [docs/architecture.md](docs/architecture.md).

Стек: Python 3.12, aiogram 3.31, FastAPI (health), PostgreSQL 17,
SQLAlchemy 2 (async) + Alembic, Pydantic v2 + pydantic-settings,
`cryptography` (AES-256-GCM), официальный `mcp` SDK v2, pytest.

```
src/jarvis/
├─ config/        настройки и проверка конфигурации
├─ domain/        типы, перечисления, политика временных групп
├─ db/            ORM-модели, сессии, миграции (alembic/)
├─ repositories/  доступ к данным
├─ services/      задачи, знания, поиск, документы, секреты, подтверждения, backlog
├─ agent/         инструменты, оркестрация, бюджеты, очередь, роутинг «Джарвис»
├─ research/      интерфейс веб-поиска (none | fake)
├─ conversation/  диалоговый движок, состояния, превью операций, разбор дат
├─ ai/            провайдеры LLM (OpenCode Go, fake, none), structured output
├─ transcription/ провайдеры распознавания речи
├─ documents/     шифрованное файловое хранилище
├─ security/      авторизация, крипто, redaction
├─ bot/           Telegram-хендлеры, клавиатуры, middlewares
├─ mcp/           MCP-сервер (read-only)
└─ workers/       фоновая уборка (TTL, сироты)
```

## Быстрый старт (Docker Compose)

Требования: Docker + Docker Compose, сервер или локальная машина.

```sh
git clone <repo> && cd Jarvis
cp .env.example .env

# 1. Ключи шифрования (значения вставить в .env, не коммитить)
python scripts/init_key.py

# 2. В .env заполнить:
#    POSTGRES_PASSWORD=<случайный пароль>
#    TELEGRAM_BOT_TOKEN=<токен от @BotFather>
#    TELEGRAM_ALLOWED_USER_IDS=<ваш user id>
#    MCP_AUTH_TOKEN=<случайная строка>   (если нужен MCP)
#    AI_PROVIDER=opencode_go, OPENCODE_GO_API_KEY=<ключ>   (по желанию)

docker compose up -d --build
docker compose ps          # все сервисы healthy
```

Миграции применяются автоматически на старте сервиса `app`. Проверка: напишите
боту `/start`, затем `/diagnostics`.

### Локальный запуск (без Docker, с VPN/прокси)

Постгрес можно оставить в Docker, а приложение запускать процессом на хосте
(так проще с VPN: `httpx` сам читает системный прокси Windows, `aiohttp` —
нет, поэтому для Telegram укажите `BOT_PROXY`):

```sh
docker compose up -d postgres
python -m venv .venv && .venv\Scripts\activate
pip install -e ".[dev]"
alembic upgrade head
python -m jarvis.main
```

`BOT_PROXY=http://127.0.0.1:10809` (или `socks5://...`) — адрес вашего
VPN-клиента; в проде на VPS оставьте пустым. Подробности —
[docs/deployment.md](docs/deployment.md).

### Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Узнайте свой user id (например, у [@userinfobot](https://t.me/userinfobot))
   и внесите в `TELEGRAM_ALLOWED_USER_IDS` (через запятую или JSON-списком).
3. Пустой allow-list = бот не отвечает **никому**; в prod-режиме с пустым
   allow-list приложение откажется запускать бота.

### AI-провайдер: OpenCode Go

Настройка в `.env`:

```sh
AI_PROVIDER=opencode_go
OPENCODE_GO_API_KEY=<ключ из консоли OpenCode>
AI_MODEL=deepseek-v4.1-flash
```

Важно (проверено по документации OpenCode Go): у моделей три семейства
протоколов. Этот адаптер поддерживает **OpenAI-совместимый `/chat/completions`** —
к нему относятся `deepseek-v4.1-flash`, `deepseek-v4-pro`, `glm-5.3*`,
`kimi-k2.6/k2.7`, `longcat-2.0`, `mimo-*` и др. Модели семейств `/messages`
(Claude, MiniMax, Qwen) и `/responses` (GPT, Grok) требуют отдельного адаптера —
выберите модель из chat-completions-семейства или напишите свой адаптер
(интерфейс `AIProvider` в `src/jarvis/ai/provider.py`).

Без AI (`AI_PROVIDER=none`) система работает в ограниченном режиме: команды,
поиск, задачи по кнопкам работают; любой текст предлагается сохранить как
заметку. Никакой фальшивой имитации AI нет.

### Транскрибация

Голосовые поддерживаются через OpenAI-совместимый `/audio/transcriptions`
(подходит OpenAI, Groq, локальный whisper-сервер):

```sh
TRANSCRIPTION_PROVIDER=openai_compatible
TRANSCRIPTION_BASE_URL=https://api.groq.com/openai/v1
TRANSCRIPTION_API_KEY=<ключ>
TRANSCRIPTION_MODEL=whisper-large-v3
```

По умолчанию (`none`) голосовые не обрабатываются, бот попросит прислать текст.

### Ключи шифрования

`python scripts/init_key.py` печатает значения `DOCUMENT_ENCRYPTION_KEY`,
`DOCUMENT_ENCRYPTION_KEY_VERSION` и `SECRETS_ENCRYPTION_KEY` — сохраните их в
`.env` на сервере (права `600`) и в менеджере секретов. **Потеря ключа =
безвозвратная потеря зашифрованных файлов и секретных значений.** Порядок
ротации описан в [docs/security.md](docs/security.md) и
[scripts/reencrypt.py](scripts/reencrypt.py).

## Команды бота

`/start` · `/help` · `/search` · `/tasks` ` /today` · `/inbox` · `/documents` ·
`/secret` · `/settings` (категории) · `/diagnostics` (сводка и backlog улучшений,
алиас `/status`) · `/export_issues` (выгрузка backlog в Markdown и JSON) ·
`/export_chat [YYYY-MM-DD]` (выгрузка диалога за день: Markdown + JSON) ·
`/cancel` (отменить сценарий или остановить агента). Естественный язык работает
независимо от команд; явное обращение «Jarvis/Джарвис, ...» идёт в AI-агент.

## MCP для OpenCode

Read-only, статический bearer-токен, доступ через ssh-туннель; секреты и
содержимое документов недоступны никогда. Инструменты: `search_knowledge`,
`search_instructions`, `get_knowledge_item`, `get_project_context`,
`search_tasks`, `find_related`.

Инструкция и пример конфига: [docs/mcp.md](docs/mcp.md),
[examples/opencode.mcp.jsonc](examples/opencode.mcp.jsonc).

## Тесты

```sh
# всё (нужен запущенный PostgreSQL из compose — используется тестовая БД jarvis_test)
python -m pytest

# только быстрые юнит-тесты без БД
python -m pytest tests/unit
```

Интеграционные и e2e-тесты сами создают/удаляют БД `jarvis_test` на сервере из
`.env` и применяют миграции; без доступной БД они честно скипаются. E2E-тесты
прогоняют реальные хендлеры через настоящий Dispatcher с фейковым Telegram
(без сети) и фейковыми AI/транскрибацией.

## Миграции


## Ограничения текущей версии

- Транскрибация и AI по умолчанию выключены — включаются конфигурацией; реальные
  ключи в CI/тестах не использовались.
- Embeddings/семантический поиск не реализованы (интерфейс поиска расширяемый;
  PostgreSQL FTS закрывает основной сценарий).
- Проекты создаются вручную (`/projects` → «Новый проект»); автоматическое
  определение проекта из текста — на усмотрение AI-промпта.
- Один владелец (единственный allow-list), без ролей и мультиарендности.
- MCP: без пагинации (до 50 записей за вызов), один статический токен.
- Массовый импорт/экспорт данных не предусмотрен (кроме выгрузки improvement
  backlog: `/export_issues` → MD + JSON).
- Improvement backlog: при недоступной БД сбои не буферизуются на диск —
  остаются только в логах.
- AI-агент: инструменты покрывают задачи, комментарии, проекты и чтение знаний;
  создание знаний/секретов/документов агент не выполняет (эти сценарии — через
  обычный диалог с подтверждением). Веб-поиск подключается провайдером
  (`WEB_SEARCH_PROVIDER`); по умолчанию выключен и агент честно об этом говорит.
  Очередь запросов — на процесс (развёртывание однопроцессное).
- Удаление документов и секретов необратимо (файлы затираются из хранилища);
  записи знаний/задачи удаляются мягко.

## Безопасность — кратко

Allow-list по user id на всех точках входа; все значимые изменения только через
подтверждение; redaction логов; AES-256-GCM с версионированным заголовком как
AAD; мастер-ключи только в `.env`; секреты и чувствительные документы не
уходят во внешний AI и MCP. Подробности и честный список остаточных рисков —
в [docs/security.md](docs/security.md).
