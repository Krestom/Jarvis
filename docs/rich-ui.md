# Rich UI: карточки с кнопками внутри сообщения

Bot API 10.3 (24 августа 2026) добавил кнопки внутрь rich-сообщений.
Экраны Jarvis переведены на этот формат: заголовок, короткий текст и
действия в одном пузыре, без клавиатуры под сообщением.

Статус: задеплоено 2026-11-13 (`6f30117`), тестовый бот остановлен.
Проверки: 463 passed, `ruff` чистый, живой прогон экранов на тест-боте
и на проде через callback-сценарий.

Официальные источники:

- [Rich messages](https://core.telegram.org/bots/api#rich-message-formatting-options)
- [RichMessageButton](https://core.telegram.org/bots/api#richmessagebutton)
- [Демо BotNews](https://t.me/BotNews/121) — карточка с CTA внутри пузыря
- [@RichTextDemoBot](https://t.me/RichTextDemoBot) — интерактивное демо

## Правила

1. Один экран — одна карточка. Заголовок → короткое пояснение → действие.
2. Не больше одной `primary`-кнопки на экран. Цвет — смысл, не украшение.
3. `success` — только подтверждённое успешное действие или завершение.
4. `danger` — только необратимое действие (удаление, архив).
5. Навигация, «Назад», «В меню» и обычная отмена — нейтральные или `link`.
6. Кнопки — в рядах по 1–3, максимум 8 в ряду; последний ряд — навигация.
7. Списки: заголовок, элементы stack-кнопками (номер + название), пагинация
   `[⬅️, К списку, ➡️]`.
8. Длинный текст — в `<details>` или `<blockquote>`, чтобы карточка не
   превращалась в полотно.
9. Все динамические значения экранируются (`esc`).
10. У каждого экрана есть текстовый fallback и обычная клавиатура — на случай
    старого клиента или отказа rich-сообщения.

## Устройство

- `src/jarvis/bot/rich.py` — `RichScreen`, отправка/редактирование,
  fallback, примитивы (`button`, `row`, `text_screen`, `markup_rows`).
- `src/jarvis/bot/screens/core.py` — главное меню, меню задач, списки,
  карточка задачи, комментарии, help.
- `src/jarvis/bot/screens/content.py` — знания, документы, секреты.
- `src/jarvis/bot/screens/diagnostics.py` — диагностика и backlog.
- `src/jarvis/bot/screens/search.py` — поиск и выбор сущностей.
- `src/jarvis/bot/handlers/render.py` — общий слой: текст + клавиатура
  автоматически превращаются в rich-карточку.

`send_rich` сначала пробует `sendRichMessage`/`editMessageText(rich_message=...)`.
При `Bad Request` отправляет обычный текст с клавиатурой. Ошибки парсинга
HTML обрабатываются в `answer_safe`.

## Ограничения

- Rich-сообщение редактируется целиком; отдельной правки кнопок нет.
- `callback.message.text` у rich-сообщения пустой — контент в `rich_message`.
- Кнопки внутри rich не являются `reply_markup`; `editMessageReplyMarkup`
  их не обновит.
- Лимиты: 32 768 символов, 500 блоков, 1–8 кнопок в ряду,
  `callback_data` 1–64 байта.
- Старые клиенты могут показать карточку проще; fallback обязателен.
- Произвольный CSS недоступен: только нативные стили и разметка rich HTML.
