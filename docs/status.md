## Операционка (как что делать)

- **Деплой на прод**: `ssh jarvis-srv` → `cd /opt/jarvis && git pull --ff-only &&
  docker compose up -d --build`; миграции применяет сервис `app` (entrypoint).
  После: `docker compose ps` и `docker compose logs --tail=30 app`.
- **Читать состояние/бэклог**: `docker compose ps`/`logs`;
  `docker compose exec -T postgres psql -U jarvis -d jarvis` (SELECT);
  владельцу — `/diagnostics` и `/export_issues` в боте. Статусы записей backlog
  менять через бота или код приложения (`ImprovementRepository`), не сырым SQL.
- **Бэкапы**: cron 04:00 (`/home/deploy/jarvis-backups`); проверка —
  `scripts/verify_backup.sh <каталог>`; тестовое восстановление — `scripts/restore.sh`
  (изолированный проект, прод не трогает).
- **Выгрузки с сервера скриптом**: вложенный python через ssh на Windows может
  побить кириллицу — кодировать вывод в base64 на удалённой стороне и декодировать
  локально.
- **Ошибки бота**: автоматически попадают в `/diagnostics` (backlog) и сообщением
  владельцу в чат; correlation id связывает запись с `docker compose logs app`.

- Файлы экспортов пишутся в том `jarvis-exports` (переживают рестарт контейнера).
- `scripts/restore.sh` восстанавливает только в тестовое окружение.
- merge дублей backlog — только через сервис (без UI в боте).
- Напоминания и утренняя сводка работают, пока процесс бота жив; адресат — первый

- Агент правит заметки, но не создаёт секреты и документы и не удаляет заметки

## Форматирование Telegram: минимализм, откат «умной» разметки (НЕ задеплоено)

**Итог итерации форматирования (17.10):** после ретестов владелец попросил
откатить всю «умную» разметку. Оставлено только:
- жирный текст (`**…**` → `<b>`) и базовая HTML-страховка фолбэка;
- пункты «•»: склейки разбиваются на строки, между пунктами пустая строка;
- пустые строки между абзацами (склеенные «…итог.Далее…» → отдельные абзацы);
- `<br>/<br/>/<BR>` → настоящий `\n` — корневой фикс: Telegram тега `<br>` не
  знает, сообщение отклонялось и фолбэк `answer_safe` склеивал текст.

Убрано: обёртка списков в `<blockquote>` (теги blockquote снимаются и у
модели), полировка карточек (`formatting.py`, `preview.py` — снова `<i>`),
правило «Источники:» отдельным абзацем, автонарезка «простыней» на абзацы.
Промпт `TELEGRAM_FORMAT_RULES` сокращён до того же минимального набора.

Тесты: 326 passed, ruff чист. Тест-бот @jartestv1_bot перезапущен 16:23.
Живой репро конвейера: пункты и пустые строки работают, цитат нет; сплошной
абзац от модели остаётся сплошным — перекраивать его больше не пытаемся.

**Мусор в ответах модели (проверка 17.10, вопрос про спатифиллум):** модель

После правки 3 из 3 живых ответов чистые. Остаточный риск: быстрая модель всё
равно может глючить — радикально лечится только сменой модели (решение владельца).

## Задачи: цепочка «категория → задача» и вопрос про срок (17.10, НЕ задеплоено)

**Что чинили (по следам живого теста владельца):** агент обещал «подтвердите
категорию — сразу заведу задачу», но после подтверждения категории задача не
создавалась — запрос приходилось повторять руками. Плюс: задача без срока
должна уточнять, нужен ли срок.

**Что сделано:**
- `create_task` при отсутствующей категории сам предлагает её создание и сразу
  готовит задачу (привязка по имени, `TaskDraft.category_name`); при
  подтверждении задачи категория находится по имени или создаётся — порядок
  кликов не важен; повторное подтверждение категории идемпотентно
  (`services/operations.py`);
- задача без срока: движок перехватывает превью (`Flow.AWAIT_TASK_DUE`) и
  спрашивает «Нужен ли срок?» — «нет/без срока» → превью задачи как есть,
  дата → `parse_human_date` кладёт дедлайн в превью. Работает и в агентском,
  и в обычном сценарии; строка из агента при этом заменяется вопросом;
- промпт агента: не обещать автоматических продолжений после подтверждения.

**Проверка:** живой сценарий владельца на реальной модели («задача в новой
категории сантехника, без срока»): вопрос про срок + предложение категории →
«без срока» → превью задачи с категорией → подтверждение → задача создана,
привязана к категории, без срока. 329 тестов, ruff чист; тест-бот перезапущен
17:06. Е2Е-тесты: цепочка категории (tools), вопрос про срок в агентском и
обычном сценариях (e2e).
