# Статус проекта и точка передачи (handoff)

Обновлено: 2026-10-16. Этот файл — краткая память проекта: где что работает,
что сделано, что осталось. При расхождениях источник истины — код и git.

## Где что работает

**Прод — сервер (Ubuntu 24.04, пользователь `deploy`):**
- `/opt/jarvis` — git-клонирование репозитория, docker compose проект `jarvis`
  (postgres 17 + app + mcp). БД чистая: история копится с 2026-10-15
  (переезд вариантом «чистый старт», данные тестового периода не переносились).
- Тот же бот: @Jarvis_tsygan_bot. **Локальный бот не запускать** — один токен =
  один поллинг, иначе конфликт (409). Для локальных прогонов — отдельный dev-бот.
- Рядом на сервере Supersport (чужой проект) — **не трогать**: у Jarvis своя
  сеть/тома, порты только на loopback (5433, 8765). Проверки соседа — docs/deployment.md §3.2.
- `.env` на сервере — копия локального, отличия: `APP_ENV=prod` (проверить!),
  `BOT_PROXY=` пусто. Ключи шифрования те же, что локально.
- Обновление: `cd /opt/jarvis && git pull && docker compose up -d --build`
  (миграции применяет entrypoint app). Бэкапы: cron `scripts/backup.sh`.

**Локальная разработка (Windows):**
- `D:\agent_projects\Jarvis`; PostgreSQL — docker compose (порт 127.0.0.1:5433)
  нужен и для локального запуска, и для интеграционных тестов (БД `jarvis_test`
  пересоздаётся автоматически).
- Тесты: `pytest -o addopts="" -q` (сейчас 238 passed), линт: `ruff check .`.
- AI-контур проверен живьём: OpenCode Go (`deepseek-v4.1-flash`), Groq
  `whisper-large-v3-turbo` (голос). Реальные ключи только в `.env` (gitignored).

**MCP:** на сервере слушает 127.0.0.1:8765; доступ с локальной машины через
туннель `ssh -N -L 8765:127.0.0.1:8765 deploy@supersport`, токен —
`MCP_AUTH_TOKEN` из `/opt/jarvis/.env`. Конфиг OpenCode — docs/mcp.md.

## Что сделано (хроника, коротко)

- **Ядро**: задачи (динамические группы), знания, комментарии, документы
  (AES-256-GCM), секреты, FTS-поиск, pending-подтверждения, TTL-уборка, MCP
  (read-only, bearer), backup/restore-скрипты.
- **Stage 2**: improvement backlog (дедуп, события, merge, порог гипотез),
  `dp.errors` → backlog, `/diagnostics`, `/export_issues` (MD+JSON), AGENTS.md.
- **Stage 3**: AI-агент — типизированные инструменты (задачи/комментарии/проекты/
  знания/backlog/web_search/пробелы), бюджеты (время/шаги/токены/циклы), отмена
  (`/cancel`), per-user очередь, роутинг «Jarvis/Джарвис» (приоритет над
  эвристиками), `entity_choice`-кнопки по реальным сущностям, `create_knowledge`
  через подтверждение (авто-sensitive для кредов).
- **Транскрибация**: Groq whisper-large-v3-turbo; лимиты/ошибки видно в чате.
- **Журнал чата**: `chat_messages` (вход/выход/голос/команды, redacted,
  retention 30 дней, `CHAT_LOG_ENABLED`), `/export_chat [дата]` → MD+JSON.
- **Деплой**: compose с ротацией логов и тюнингом, Makefile, docs/deployment.md
  (профиль сервера, 3 варианта переезда, чек-лист), фикс прав экспортов
  (`EXPORT_DIR=/data/exports` в контейнере).

## Открытые хвосты (сделать/проверить)

1. **Сервер**: применить последний коммит (`git pull && docker compose up -d
   --build`), если ещё не сделан после `3684049`; проверить `/export_chat`
   и `/export_issues` вживую.
2. **Сервер**: `APP_ENV=prod` в `/opt/jarvis/.env` (при первом старте был dev).
3. **Backlog**: отметить запись «PermissionError … 'var'» статусом
   «Реализовано» в `/diagnostics` (она уже исправлена в `3684049`).
4. **Сервер**: поставить cron-бэкапы (`scripts/backup.sh`, BACKUP_DIR вне репо),
   если ещё не поставлены.
5. Возможные улучшения на потом (кандидаты, не утверждены): персистентный том
   под `/data/exports`; UI для merge дублей backlog; реальный провайдер
   web-поиска; очистка срока в `update_task`; PostgreSQL-backed очередь агента
   (если появится второй воркер).

## Известные ограничения (осознанные, не баги)

- Очередь/отмена агента — процесс-local (развёртывание однопроцессное).
- Веб-поиск: провайдер не подключён (доступны `none` и `fake`).
- Файлы экспортов в контейнере эфемерны (уходят в Telegram; том не заведён).
- `scripts/restore.sh` восстанавливает только в тестовое окружение
  (`jarvis-restore-test`), прод-проект не трогает — по замыслу.
- merge дублей backlog — только через сервис (без UI в боте).
