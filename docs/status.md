## Операционка (как что делать)

- **Деплой на прод**: `ssh jarvis-srv` → `cd /opt/jarvis && git pull --ff-only &&
  docker compose up -d --build`; миграции применяет сервис `app` (entrypoint).
  После: `docker compose ps` и `docker compose logs --tail=30 app`.
- **Читать состояние/бэклог**: `docker compose ps`/`logs`;
  `docker compose exec -T postgres psql -U jarvis -d jarvis` (SELECT);
  владельцу — `/diagnostics` и `/export_issues` в боте. Статусы записей backlog
  менять через бота или код приложения (`ImprovementRepository`), не сырым SQL.
- **Бэкапы**: cron 04:00 (`/home/deploy/jarvis-backups`); проверка —
  `scripts/verify_backup.sh <каталог>`; тестовое восстановление — `scripts/restore.sh`
  (изолированный проект, прод не трогает).
- **Выгрузки с сервера скриптом**: вложенный python через ssh на Windows может
  побить кириллицу — кодировать вывод в base64 на удалённой стороне и декодировать
  локально.
- **Ошибки бота**: автоматически попадают в `/diagnostics` (backlog) и сообщением
  владельцу в чат; correlation id связывает запись с `docker compose logs app`.

## Известные ограничения (осознанные, не баги)

- Очередь/отмена агента — процесс-local (развёртывание однопроцессное).
- Веб-поиск: провайдер `tavily` подключён (`WEB_SEARCH_PROVIDER=tavily`,
  ключ `TAVILY_API_KEY`); лимиты бюджетов агента (1/3/8 запросов по профилям).
- Файлы экспортов пишутся в том `jarvis-exports` (переживают рестарт контейнера).
- `scripts/restore.sh` восстанавливает только в тестовое окружение.
- merge дублей backlog — только через сервис (без UI в боте).
- Напоминания и утренняя сводка работают, пока процесс бота жив; адресат — первый
  пользователь из allow-list; окно сводки — 30 минут после `NOTIFY_DIGEST_TIME`.
- Агент правит заметки, но не создаёт секреты и документы и не удаляет заметки
  (удаление знаний — кнопкой в карточке /knowledge).

## Итерация 2026-10-17 (по аудиту, коммиты после `ecbf403`)

- Веб-поиск: провайдер Tavily (`research/tavily.py`), `WEB_SEARCH_PROVIDER=tavily`.
- Единая очередь агента: голосовые запросы идут через тот же `UserSessionGate`,
  что текстовые; `/cancel` останавливает все; модульный `default_gate` удалён.
- Политика подтверждений: агентные `create_task`/`update_task`/`add_comment`/
  `create_category` — превью + кнопка (как `delete_task`/`create_knowledge`);
  несколько операций за запрос — у каждой свои кнопки.
- Агент редактирует заметки: инструмент `update_knowledge` (в т.ч. sensitive),
  превью «Изменить запись?», «Изменить» для такой операции работает.
- MCP: `MCP_INCLUDE_SENSITIVE=true` — чувствительные заметки видны MCP;
  секреты — никогда (решение владельца).
- Контекст агента не стирается при занятой очереди (`queue_timeout`).
- Списки задач из NL («на сегодня», «на дату») — кликабельные (кнопки карточки).
- Мёртвая фича «Связи» удалена: `entity_links`, `find_related`, кнопки «🔗 Связи»,
  типы операций `CREATE_LINK`/`UPDATE_KNOWLEDGE`→(теперь живой)/`UPDATE_SECRET`
  (миграция `b7f3c1a2d4e6`).
- Мелочи: `redact()` гипотез; `update_task` умеет убрать срок (`due_at=null`);
  том `jarvis-exports` для файлов экспорта.
- Инициативные уведомления: сводки по расписанию (`NOTIFY_DIGEST_TIMES` —
  08/09/12/15/18/22, вечерняя расширенная: закрыто+осталось+завтра) и
  пред-напоминание за час до срока (`NOTIFY_BEFORE_DUE_MINUTES`); напоминания
  больше не голодают при >5 задач (лимит прохода + добор в следующих).
