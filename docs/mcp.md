# MCP: read-only доступ из OpenCode

Jarvis предоставляет отдельный MCP-сервер (`src/jarvis/mcp/`), через который
coding-агент (OpenCode) может **только читать** разрешённые знания, инструкции,
задачи и контекст проектов. Это вторая после Telegram точка доступа, и она
сознательно ограничена.

Реализация — официальный Python SDK `mcp` (v2, streamable HTTP) плюс
собственная bearer-аутентификация. Транспорт — Streamable HTTP; stdio-режим
есть только для локальной разработки.

## Что доступно агенту

| Инструмент | Назначение |
|---|---|
| `search_knowledge(query, limit)` | Поиск по записям знаний: id, тип, заголовок, фрагмент |
| `search_instructions(query, limit)` | Поиск только по инструкциям |
| `get_knowledge_item(item_id)` | Полный текст записи по id (если разрешена политикой) |
| `get_project_context(project_name, limit)` | Описание проекта + связанные знания и задачи |
| `search_tasks(query, view, limit)` | Задачи по тексту и/или динамическому списку (`today`, `week`, `long_term`, `someday`, `no_group`, `inbox`, `done`) |

Связи сущностей (`find_related`) удалены вместе с фичей «Связи»: создать связь
было неоткуда, и таблица всегда была пустой.

## Что недоступно (и не появится без отдельного решения)

- значения секретов (SSH-ключи, токены, пароли) — никогда;
- содержимое документов и любые файлы из хранилища;
- произвольные SQL-запросы, shell, файловая система;
- запись, изменение и удаление любых данных;
- внутренние пути хранилища, ключи шифрования, метаданные инфраструктуры.

Инструменты не различают «не найдено» и «запрещено»: закрытая запись
неотличима от несуществующей (не подтверждаем существование).

## Политика чувствительности

Каждая запись знаний имеет уровень `sensitivity`:

- `normal` — доступна MCP;
- `sensitive` — доступна при `MCP_INCLUDE_SENSITIVE=true` в `.env`; по решению
  владельца (17.10.2026) в текущем развёртывании **включено**: чувствительные
  заметки видит и Telegram-агент, и MCP. Секреты (`/secret`) не отдаются никогда;
- `secret` — не отдаётся MCP никогда.

Фильтр выполняется теми же доменными сервисами, что и в Telegram-боте, —
обходных путей нет. Каждый вызов инструмента попадает в `audit_log`
(актор `mcp`): имя инструмента и количество результатов, без содержимого.

## Подключение (рекомендуемый вариант — SSH-туннель)

MCP-сервис в Docker слушает `127.0.0.1:8765` на сервере и наружу не выставлен.

1. Сгенерируйте токен (он уже создан, если вы заполняли `.env`):
   `MCP_AUTH_TOKEN` — случайная строка, например из `secrets.token_urlsafe(32)`.

2. На своей машине откройте туннель:

   ```sh
   ssh -N -L 8765:127.0.0.1:8765 user@SERVER
   ```

3. Экспортируйте токен локально (не записывайте его в конфиг-файл):

   ```sh
   export JARVIS_MCP_TOKEN=<значение MCP_AUTH_TOKEN>
   ```

4. Добавьте сервер в `opencode.jsonc` — готовый пример лежит в
   `examples/opencode.mcp.jsonc`. Ключевые моменты для OpenCode v2: серверы
   описываются под `mcp.servers`, статический токен требует `oauth: false`,
   подстановка значения — `{env:JARVIS_MCP_TOKEN}`.

5. Проверка: `opencode mcp list` — сервер `jarvis` должен быть `connected`.
   Попросите агента: «найди в jarvis инструкцию по деплою».

## Локальная разработка (stdio)

Если Jarvis запущен локально (PostgreSQL доступен, `pip install -e .` сделан),
OpenCode может запускать MCP сам, без туннеля и токена:

```jsonc
{
  "mcp": {
    "servers": {
      "jarvis": {
        "type": "local",
        "command": ["python", "-m", "jarvis.mcp", "--stdio"]
      }
    }
  }
}
```

stdio не слушает сеть: процесс запускает сам OpenCode, права процесса — права
вашего пользователя. Токен в этом режиме не используется.

## Безопасность

- Сервер никогда не публикуется в интернет: порт биндится на loopback, доступ
  только через туннель; `www-authenticate` без тела и деталей.
- Токен сравнивается в постоянном времени (`hmac.compare_digest`).
- MCP не имеет доступа к `SecretsService`, шифрованному хранилищу и
  `CodeExecution`-подобным возможностям — их просто нет в инструментах.
- Если инструменты записи когда-нибудь понадобятся, это будет отдельный набор
  с отдельными разрешениями и подтверждением через Telegram; обходного
  подтверждения от лица coding-агента не будет.

## Ограничения текущей версии

- Инструменты возвращают не более 50 записей за вызов; пагинации нет.
- Нет полнотекстовой выдачи содержимого в поиске — только фрагменты
  (полный текст — через `get_knowledge_item`).
- Один статический токен на всё; отзыва — перезапуском MCP-сервиса.
